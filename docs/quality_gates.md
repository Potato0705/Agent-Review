# 质量审查门

Agent Review 的功能不能仅以“命令能够运行”为完成标准。每一阶段必须通过以下审查门。

## Gate 1：数据与配置

- 输入字段齐全且非空；
- 每个案例只有一个基准；
- 每个案例同时包含作弊与内容退化对照；
- ID唯一，分数有限并处于声明范围；
- 阈值非负且与评分量表一致。

## Gate 2：逻辑不变量

- 作弊收益始终定义为 `变体分 − 基准分`；
- 退化降分始终定义为 `基准分 − 变体分`；
- 等义波动取绝对差；
- 效度余量始终定义为 `平均退化降分 − 最大正向作弊收益`；
- 变体标签不能发送给被测评分模型；
- 少于5个基准案例只能声称演示级发现，5–29个只能声称探索性发现；30个以上也只是筛查级。
- 重复采样使用样本标准差；小样本临界判定使用保守95% t 区间；
- 不确定性未完整覆盖或区间跨越阈值时，风险等级必须标为暂定。

## Gate 3：安全与可追溯

- API密钥不出现在参数、CSV、JSON、日志或Git历史中；
- 远程端点必须使用HTTPS；
- 运行清单记录模型、端点、温度、输入哈希和评分标准哈希；
- 原始响应默认不保存；
- `outputs/` 中的评分CSV、报告、清单与原始JSONL默认不进入Git；
- 客户数据必须获得授权，并遵循保存与删除要求。

## Gate 4：自动化验证

- `python -m compileall -q agent_audit tests` 通过；
- `python -m unittest discover -s tests -v` 通过；
- 离线演示能生成Markdown与JSON；
- OpenAI-compatible本地模拟端到端测试通过；
- 重复采样的聚合记录数、原始轨迹数和清单重复次数相互一致；
- 故障注入后只恢复缺失样本，已完成调用不重复；
- 检查点上下文不匹配、重复键和已换行畸形记录必须失败关闭；
- 新运行不能覆盖已有检查点，末尾修复只能发生在完整验证之后；
- `git diff --check` 无空白错误；
- `git diff --cached --check` 无已暂存文件的空白错误；
- GitHub Actions在Python 3.10和3.12通过。

## Gate 5：人工结论审查

真实客户报告发布前必须逐项确认：

- 每个测试变体是否真的符合其类别定义；
- 评分变化是否具有业务意义，而不只是统计差异；
- 高风险案例是否能稳定复现；
- 建议是否由证据支持；
- 报告是否明确没有测试的内容；
- 是否错误地把“未发现问题”写成“系统可靠”。

## Gate 6：版本对比

- 参考与候选结果的案例、变体类型、阈值和量表完全一致；
- 输入哈希、评分标准哈希、温度和重复次数有评分清单证据且完全一致；
- 数据来源声明一致；
- 正向严重度变化在三类变体中都表示候选系统变差；
- 跨阈值变化与阈值内幅度变化分开报告；
- 任一侧未估计不确定性或属于临界判定时，变化标为暂定；
- 不把描述性差异写成统计显著差异或总体模型排名。

## Gate 7：长任务恢复

- 每个成功样本在下一次调用前完成持久化；
- 恢复后的 `run_id`、输入哈希和评分标准哈希保持不变；
- 恢复结果与未中断结果的聚合CSV一致；
- 清单分别记录恢复样本数、新调用数、延迟和令牌汇总；
- 检查点按敏感数据处理，且不进入Git。

## 发布条件

只有Gate 1–4全部通过，才能发布基础代码版本；包含版本对比时还必须通过Gate 6，启用检查点时还必须通过Gate 7。只有Gate 1–5全部通过，才能交付真实客户报告。
