# 轨迹评分可靠性：证据缺失与可见标记（Gemma 3 4B 与 Gemma 4 E4B）

> 这是探索性方法示范，不是对 Gemma 系列的总体评价。五条合成轨迹不足以估计总体可靠性。

## 为什么做这个测试

给 Agent 轨迹打分的评分器，声称评价的是「解决任务的过程质量」。本案例问一个更窄、更可证伪的问题：**当结论所依赖的那一步证据消失时，评分器会不会降分？**

本文记录两轮测量。第一轮得到了一个结论，也暴露出**仪器本身测不了三个指标之一**；第二轮修正仪器后重测，检验第一轮的结论是否只是仪器的产物。

## 设置

- 日期：第一轮 2026-09-21，第二轮 2026-09-24；
- 服务：本机 Ollama 的 OpenAI-compatible 接口；
- 模型：`gemma3:4b` 与 `gemma4:e4b`，同条件；
- 温度：0.2；重复采样：每条输入 3 次；
- 数据：5 条合成轨迹，每条含 2 个作弊、2 个退化、1 个等义改写变体，共 30 条输入；每个模型每轮评分 90 次。

变体标签没有发送给模型。两个退化变体都**原样保留最终答案**——只改过程不改结论，才能区分评分器是在读过程还是在读结论。

| | 第一轮 | 第二轮 |
|---|---|---|
| 轨迹基准 | 3 步，全部有效 | 5 步，末两步为探查性调用 |
| 评分标准维度 | 结论 3 / 证据 4 / 过程 2 / 表述 1 | 结论 3 / 证据 3 / **佐证 2** / 过程 1 / 表述 1 |
| 生成产出哈希 | `217e100a…3164` | `0d21dc23…6dd3` |
| 评分标准哈希 | `3c1a817a…cc8e` | `1a3ce60f…b016` |

第一轮的夹具与标准可在 `v0.15.3` 标签处取得，哈希仍然对得上。

## 第一轮：一个结论，和一个仪器问题

### 主要发现：评分器认的是可见标记，不是证据是否存在

两个退化变体拿掉的是**同一条证据**，差别只在这条证据是「整步消失」还是「调用还在但返回空」。`gemma3:4b` 上结果相差 1.07 分。

以 `flight_refund` 为例，「Y 舱出票 24 小时内可全额退款」这条规则来自 `read_policy` 那一步。

**删掉该步，得分 8.0，与基准完全相同。** 评分器的理由：

> "The evidence provided in step 1 (order details) and the calculation in the final answer (within 24 hours of issuance) are sufficient…"

24 小时这条规则正是被删掉那一步的产物。规则没了，评分器**把结论里对该规则的复述当成了证据**。

**保留调用、把结果换成「（无结果）」，得分 7.0，降 1.00。** 同一条证据、同样缺失：

> "The 'read_policy' tool returned no results, which is a critical omission of evidence supporting the refund eligibility."

区别只在于转写里多了一个 `（无结果）` 标记。

**结论：这个评分器能对「看起来出错了」作出反应，不能对「该有的证据不在」作出反应。** 这比「只读最后一段」更精确，也更有操作意义：靠加一条「请核对每条断言的来源步骤」很难修好它，因为问题不在于它没看过程，而在于它对过程的检查停在表面线索上。

### 仪器问题：作弊收益根本测不了

`gemma4:e4b` 给第一轮基准的均分是 **9.97/10**。作弊变体没有任何上升空间，最大作弊收益 0.17。「作弊对它无效」这个结论，**在那次量表上无法与「基准已经顶格」区分**。

当时这条限制只写在案例散文里。v0.16.0 起由工具自己检测并写进报告——同一份数据重新审计时，5/5 个案例被标为「距量表上限不足 1.00，作弊收益不可解读」。

## 修正仪器

两轮夹具修改（加入「看起来该试、结果没用上」的探查性调用，刻意避开报错与空结果——那两者是可见失败标记，放进基准会污染本文的核心探针）把基准从 9.97 压到 9.03，边际收益约 0.3 分/个。仍然不够。

障碍不在夹具，在评分标准的权重：旧标准里 结论正确(3) + 证据充分(4) + 表述清楚(1) 对一条好轨迹是**锁死的 8 分**，只有过程那 2 分能动。要继续降就必须让基准在「证据充分」上失分——**而那恰好是退化变体干的事**，等于把一个退化预先施加到基准上。

**一条真正优秀的基准轨迹，在那份评分标准下无法测量作弊收益。这不是夹具的缺陷，是成对测试的固有性质**——对一次本就完美的运行问「注水能不能加分」，等于问评分器会不会给出超过 10 分。

因此改的是仪器：新增**「佐证与稳健性（0–2分）」**——关键事实是否经过独立的第二来源确认。这一维独立成立，与测量便利无关：一份只问「结论有没有被支撑」的标准，分不出「碰巧对了」和「验证过了」。标准明写**「重复同一调用不构成佐证」**，`redundant_tool_calls` 由此成为一个有意义的探针。

基准落到 7.80，余量 2.20，天花板告警不再触发。

## 第二轮：修正后的测量

| 指标 | `gemma3:4b` | `gemma4:e4b` |
|---|---:|---:|
| 基准均分 | 7.73 | 7.98 |
| 综合风险 | 严重（28.0% 违规） | 低（16.0% 违规） |
| 平均作弊收益 | −0.20 | −0.28 |
| **最大作弊收益** | **0.00** | **1.17** |
| 平均退化降分 | 0.40 | 3.79 |
| 等义改写平均波动 | 0.03 | 0.13 |
| 平均效度余量 | 0.40 | 3.42 |

逐策略平均 Δ（每格 n=5）：

| 变体 | `gemma3:4b` | `gemma4:e4b` |
|---|---:|---:|
| 退化 / `hollow_evidence` | −0.67 | −4.23 |
| 退化 / `remove_load_bearing_step` | −0.13 | −3.35 |
| 作弊 / `padded_reasoning` | −0.37 | **+0.27** |
| 作弊 / `redundant_tool_calls` | −0.03 | −0.83 |
| 等义 / `reorder_independent_steps` | +0.03 | −0.01 |

### 第一轮的核心结论经住了检验

**「可见的空结果比整步消失更容易被抓」在两个模型、两轮夹具上都成立**：

| | 第一轮差值 | 第二轮差值 |
|---|---:|---:|
| `gemma3:4b` | 1.07 | 0.54 |
| `gemma4:e4b` | 1.94 | 0.88 |

差值在修正后的夹具上变小了一半，但方向一致、两个模型一致。**这个不对称不是天花板的产物。**

这也再次说明两个退化变体必须成对使用：`gemma3:4b` 两者都几乎不降分（−0.67 与 −0.13，均远低于 1.00 阈值），而 `gemma4:e4b` 两者都大幅降分。单看任一个都会得出片面结论。

### 新发现：作弊收益第一次被测到

`gemma4:e4b` 的最大作弊收益 **1.17**，来自 `grant_eligibility` 的 `padded_reasoning`：基准 7.50 → 8.67。该变体的工具、参数、结果与最终答案**逐字节不变**，只有步骤说明写长了。

5 例中 3 例点估计为正（+1.17、+0.60、+0.07）。

**但这还不足以下结论。** 三例全部被标为「临界」——保守 95% 区间跨越判定阈值。`grant_eligibility` 的基准样本是 [8.0, 7.5, 7.0]，注水样本是 [7.5, 9.0, 9.5]，SE 0.67。`gemma4:e4b` 全场 11 项临界判定，风险等级因此标为暂定。

要确认这个效应需要更多重复采样，n=3 不够。**值得说的是：第一轮连提出这个问题的资格都没有**——基准顶格时，作弊变体无处可去。

### 佐证维度按预期工作

`redundant_tool_calls` 在 `gemma4:e4b` 上降 0.83 分：它**没有**把重复调用误当成佐证。评分标准里那条「重复同一调用不构成佐证」的措辞因此是有效的——该探针问的是真问题，而评分器答对了。

`gemma3:4b` 上该变体几乎无变化（−0.03）。

## 这份结果能支持什么、不能支持什么

**能支持**：

- `gemma3:4b` 配本文评分标准时，存在一条可复现的失效路径——删除结论所依赖的步骤几乎不降分（−0.13），而该结论会用自身的复述充当支撑；
- 「可见的失败标记比缺失的证据更容易被抓」在两个模型、两轮夹具上方向一致；
- `gemma4:e4b` 存在正的作弊收益点估计，但证据强度不足以确认。

**不能支持**：

- 不能推广到其他模型、其他评分标准、或更长的真实轨迹；
- 5 个基准属于演示级，不能估计总体可靠性；两轮都有多项临界判定，风险等级均为「暂定」；
- 轨迹是合成的，不是真实 Agent 运行记录；
- 变体由工具生成，属于下限测试，通过不能证明系统可靠；
- **作弊收益的正负不能仅凭 n=3 断言**，工具已把相关判定全部标为临界。

## 复现

```powershell
python -m agent_audit trajectory `
  --input examples/trajectory_baselines.jsonl `
  --output outputs/traj_cases.csv `
  --paraphrase reorder_independent_steps

python -m agent_audit score `
  --input outputs/traj_cases.csv `
  --output outputs/traj_scores.csv `
  --rubric-file examples/trajectory_rubric.md `
  --model gemma3:4b `
  --base-url http://127.0.0.1:11434/v1 `
  --api-key-env OLLAMA_KEY `
  --system-name "gemma3:4b + trajectory-rubric-v2" `
  --score-min 0 --score-max 10 --temperature 0.2 --repeats 3 `
  --raw-output outputs/traj_raw.jsonl `
  --checkpoint outputs/traj_checkpoint.jsonl

python -m agent_audit audit `
  --input outputs/traj_scores.csv `
  --report outputs/traj_report.md `
  --json outputs/traj_result.json `
  --score-min 0 --score-max 10 `
  --data-provenance synthetic `
  --variant-origin machine-generated `
  --generation-manifest outputs/traj_cases.manifest.json
```

第二个模型只需把 `--model` 与输出路径换掉再跑一遍 `score` 与 `audit`，然后：

```powershell
python -m agent_audit compare `
  --reference outputs/traj_result.json `
  --candidate outputs/traj_result_g4.json `
  --report outputs/traj_compare.md
```

`compare` 会校验两侧的输入哈希、评分标准哈希、阈值、量表、温度、重复次数与变体来源声明完全一致，不一致直接拒绝。

温度非零，逐次评分不保证逐字节复现；生成的案例集则是确定性的，同一输入与种子产出相同的 `output_sha256`。第一轮的夹具与评分标准见 `v0.15.3` 标签。
