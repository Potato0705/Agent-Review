# Agent Review 作品集说明

本文件用于简历、作品集、面试和项目介绍。所有表述都限定在仓库已有证据范围内，不把探索性实验包装成生产级认证。

## 一句话定位

构建了一套面向 LLM 评分器与 Agent 评测系统的可追溯可靠性审计工具，通过成对干预测试识别表面作弊奖励、内容退化漏检、等义改写不稳定和版本回归；在 Agent 轨迹评分器上发现了一条可复现的失效路径。

## 我解决的问题

普通准确率、相关性或单次人工抽查无法回答：评分器是在识别目标质量，还是在奖励篇幅、关键词和表达形式。对 Agent 轨迹评分器还有一个更尖锐的问题：**它是在读过程，还是只在读最后一段答案？**

Agent Review 把每个基准样本与三类受控变体配对，并把变化方向、阈值、不确定性和运行上下文保存为可复核证据。

## 最值得讲的一个发现

在我们的测试里，给 Agent 轨迹打分的 **`gemma3:4b` 把结论对某个前提的复述，当成了该前提的证据。**

一条退款查询轨迹里，「24 小时内可全额退款」这条规则来自 `read_policy` 那一步。把这一步整个删掉、最终答案原封不动，评分**一分不降**——评分器的理由是「最终答案里的计算（出票后 24 小时内）已经足够」。而那条规则恰恰是被删掉那一步的产物。

同一条证据、同样缺失，只要保留调用而把结果换成「（无结果）」，它立刻判为「关键证据缺失」并降分。

结论：**这个评分器对「看起来出错了」有反应，对「该有的证据不在」没有反应。** 这比「只读最后一段」更精确，也更有操作意义——加一句「请核对每条断言的来源」很难修好它，因为问题不在于它没看过程，而在于它的检查停在表面线索上。

这个不对称经住了检验：在两个模型、两轮夹具上方向一致；修正仪器、消除天花板效应后重测，依然成立。

## 已实现能力

- 六个子命令：离线审计、模型评分、版本对比、文本变体生成、模型辅助等义改写、Agent 轨迹变体生成；
- **Agent 轨迹变体的三族后置条件全部严格可判定**——文本模态里等义改写无法机器证明，轨迹上可以；
- 变体生成只依据人工标注的承重内容，工具不推断；每个变体必须通过其类别的后置条件才会写出；
- 调用 OpenAI-compatible 模型，并严格解析分数、理由和令牌用量；布尔值、非有限数、夹杂散文一律按不可信输入处理；
- 重复采样，计算样本标准差、均值差标准误和保守 95% t 区间；证据不足时风险与版本变化标记为暂定；
- **审计会声明自己测不了什么**：基准分贴近量表上下限时，自动标出对应指标不可解读，而不是报一个会被误读的零；
- 输入、评分标准与生成运行的 SHA-256 构成证据链，把「变体由机器生成」从一句自述变成可验证的事实；
- 模型改写只作为草稿，须人工批准才能入集；改写模型与评分模型相同时审计直接拒绝（循环论证）；
- 逐样本 JSONL 检查点恢复长任务；自包含 HTML 报告转义全部不可信内容并使用限制性 CSP。

## 可核验证据

- **自动化测试 669 项，行覆盖率 99.8%，79 个变异体全部被捕获**；变异门禁逐一证明测试能区分正确与错误行为，而不只是「代码跑过了」；
- **三篇公开案例**，均为探索性方法示范：
  - 议论文评分：5 个基准、15 个配对变体、每条 3 次，共 60 次本地评分；
  - 同条件版本对比：`gemma3:4b` 与 `gemma4:e4b` 各 60 次调用，比较前核对输入、评分标准、温度、重复次数、阈值和量表；
  - **Agent 轨迹评分**：两轮、两个模型，每模型每轮 90 次，共 360 次调用；
- 故障恢复：20 条样本全部从检查点恢复，新增模型调用为 0，恢复前后评分 CSV 哈希一致；
- 从零验收：发布门会克隆提交树、建干净虚拟环境、执行 README 里的命令本身，并已验证它能抓住文档与代码的漂移。

这些证据证明工具流程、可追溯性和防误读机制可以工作，也证明上面那条失效路径可复现。它们**不证明**任一模型总体优于另一模型，不证明结论能推广到真实（而非合成的）Agent 轨迹，也不证明系统适合真实教育或业务决策。

## 关键工程取舍

1. **先做效度筛查，再做排行榜。** 比较受控变体相对同一基准的变化；审的是评分器，不产出 Agent 排行榜。
2. **默认失败关闭。** 缺少运行指纹、比较条件不一致、标注越界或来源声明自相矛盾时直接拒绝继续。
3. **把不确定性与不可测写进结论。** 证据不足显示「暂定」；指标因量表余量不可解读时，由工具自己声明，而不是靠作者在散文里记得写一句。
4. **只让无歧义的检查充当闸门。** 为等义改写设计的数字与否定词检查实测误拦 5 个人工真改写中的 2 个，因此降级为提示——40% 的误拦率会训练审阅者忽略闸门，比没有检查更糟。
5. **改仪器，不扭曲被测物。** 示例夹具测不了作弊收益时，两轮修改夹具只换来 0.3 分/轮，于是按预设上限停手，转而给评分标准补上缺失的「佐证与稳健性」维度。

## 面试展开顺序

1. **从那个发现讲起。** 用退款轨迹的例子说明「删掉证据、结论不变、分数不变」，以及它为什么比「只读结尾」更有操作意义；
2. 说明为什么两个退化变体必须**成对使用**：一个暴露失效，另一个是证明评分器并非迟钝的对照组，单看任一个都会得出相反结论；
3. 说明**我怎么知道它是真的**：修正仪器后重测，不对称仍然成立，不是天花板效应的产物；
4. 讲一次**被数据推翻的判断**：我先认为顶格是夹具的问题，又自我纠正成「评分器宽松」，结果用 3 次调用证明这条纠正本身也错了——教训是两次都在用间接推理替代一次直接实验；
5. 说明工程上的防误读机制：变异测试、证据链哈希、审计自我声明不可测的指标；
6. 最后主动说明限制：5 个基准、合成轨迹、作弊收益的正估计在 n=3 下全部为暂定，且至今没有真实客户数据校准。
